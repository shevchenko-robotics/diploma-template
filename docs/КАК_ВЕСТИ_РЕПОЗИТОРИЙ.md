# Как вести репозиторий выпускной работы

## Начало

1. На странице шаблона нажмите **Use this template → Create a new repository**.
2. Назовите репозиторий по теме работы латиницей через дефис, например `mobile-robot-navigation`.
3. Заполните README: тема, автор, цель и задачи. Удалите строку «Шаблон…».

## Правила

- **Коммитьте регулярно** — хотя бы раз в неделю, пока идёт работа. История коммитов показывает ход работы лучше любого отчёта.
- **Пишите понятные сообщения коммитов:** «Добавил расчёт привода», а не «update» или «.».
- **Храните исходники, а не только результаты:** модели CAD вместе с экспортом в STEP и PDF, код вместе с инструкцией по запуску.
- **Не храните мусор:** временные файлы, сборки и резервные копии уже исключены в `.gitignore`.
- **Отмечайте этапы метками** (tag): `predzashchita`, `zashchita`. Так легко вернуться к версии, которую вы показывали.

## Большие файлы

Тяжёлые модели, видео и архивы лучше хранить через [Git LFS](https://git-lfs.com) — расширения уже прописаны в `.gitattributes`. Установите LFS один раз командой `git lfs install`. Без LFS файлы тоже сохранятся, но репозиторий будет быстро расти.

Файлы больше 100 МБ GitHub не примет: такие видео выкладывайте на внешний ресурс и оставляйте ссылку в README.

## Приватность

Если работа содержит закрытые данные предприятия, сделайте репозиторий приватным (Settings → Danger Zone → Change visibility) и добавьте руководителя в Collaborators.
